# NotifyRelay

Android端末に届く通知（タイトル・本文）を、指定したAPIエンドポイントにJSONでPOSTするアプリです。

## 使い方

1. Android Studioでこのプロジェクトフォルダを開く（`File > Open` でルートフォルダを選択）
   - Gradle同期時にGradle本体（8.7）が自動ダウンロードされます
2. 実機（Android 11以降）にビルド・インストール
3. アプリを起動し、右上の「設定」から以下を入力
   - APIのURL
   - タイトル・本文のJSONパラメータ名（未入力時は `title` / `body`）
   - 転送したいアプリにチェック
   - ログの保存件数を選択（デフォルト100件）
   - 「通知アクセスの設定を開く」から本アプリに通知アクセスを許可
   - 「バッテリー最適化の設定を開く」から最適化除外を許可（推奨）
   - 「保存」を押す
4. メイン画面に戻り、「通知転送を有効にする」をON
5. 「テスト送信」でAPI疎通を確認（メイン画面のログにOK/NGが表示されます）

## APIに送られるJSONの形式

```json
{
  "title": "通知のタイトル",
  "body": "通知の本文"
}
```
キー名は設定画面で変更できます。常に `POST` / `Content-Type: application/json` で送信されます。

## 実装メモ

- `NotificationRelayService`（`NotificationListenerService`）が全通知を受け取り、有効化チェック→自アプリ除外→対象アプリ選別→本文抽出→送信、の順に処理します
- 送信結果（成功/失敗、HTTPステータスやエラー内容）はメモリ上のログに記録され、メイン画面にリアルタイム表示されます
- ログの保存件数は設定画面から選べます（なし / 50件 / 100件 / 300件 / 無制限、デフォルト100件）。「なし」を選ぶと通知は転送されますがログには残りません。「無制限」は際限なく溜まるため、通知が多いアプリを対象にする場合はメモリ使用量に注意してください
- ログはいずれの設定でも永続化はしておらず、アプリのプロセスが終了すると消えます（アプリ再起動後も保持したい場合は別途DB等での永続化が必要です）
- 設定（URL・パラメータ名・有効フラグ・対象アプリ）は `SharedPreferences` に保存され、アプリ再起動後も維持されます
- 対象アプリはパッケージ名で保存し、表示上はアプリ名（ラベル）を出しています
- 自アプリ自身の通知は常に除外されます（ループ防止）

## 既知の制約・注意点

- 通知アクセスは、OS側の設定画面でユーザーが手動で許可する必要があります（コード側からは自動付与できません）
- 一部端末（Xiaomi/OPPO/Huaweiなど）はメーカー独自の省電力機能により、バッテリー最適化除外だけでは不十分でサービスが止まることがあります。その場合は端末側の「自動起動許可」「保護されたアプリ」等の設定も確認してください
- 通知本文にはパスワードや認証コードなど機微な情報が含まれる場合があります。送信先APIは必ずHTTPS化してください
- `AndroidManifest.xml` に `QUERY_ALL_PACKAGES` 権限を使っています。個人利用・野良配布であれば問題ありませんが、Google Playに公開する場合はポリシー上の制約があるため対応が必要です
